# site/ — 웹사이트

이 폴더에는 <https://davian-lab.github.io/travel-guide/>의 코드와 데이터가 있다. 레포의 마크다운이 유일한 원본이고, 이 사이트는 그것을 브라우저에서 읽어 보여 주기만 한다. 콘텐츠를 쓰는 규칙은 [../AGENTS.md](../AGENTS.md) §7에 있다.

## 어떻게 동작하나

1. GitHub Pages가 `main` 브랜치 루트를 그대로 내보낸다 (Settings → Pages → Deploy from a branch → `main` / `(root)`). 빌드 단계는 없다.
2. 루트의 `.nojekyll` 덕분에 `.md` 파일이 원문(`text/markdown`)으로 나간다. **이 파일을 지우면 사이트가 깨진다.**
3. `index.html`이 `site/app.mjs`를 부르고, 앱이 `countries/README.md` → 국가 README → 각 국가 `## 6. 도시 목록`의 도시 문서 순서로 마크다운을 모두 읽는다 (약 60개이며, 따로 관리하는 목록은 없다).
4. `site/parse.mjs`가 markdown-it으로 그리면서 꼬리표·장소·학회 주석을 뽑아 칩·후기 수·학회 목록을 만든다. 해석에 실패해도 글은 그대로 보인다.
5. 주소는 `?p=<국가>/<도시>` 같은 쿼리로 나타내고, 제목 앵커는 GitHub와 같은 id(`#8-주의사항`)를 쓴다.

GitHub Pages는 응답을 10분 동안 캐시한다(`max-age=600`이며 바꿀 수 없다). 그래서 수정한 뒤 사이트에 반영되기까지 최대 10분이 걸린다. 바로 확인하려면 사이트 아래쪽의 "최신 내용 불러오기" 버튼을 누른다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `../index.html` | 진입점. 검색 노출 차단(noindex), 외부 요청 차단(CSP), 링크 미리보기 제목 |
| `app.mjs` | 불러오기, 주소 해석, 화면 전환, 스크롤 |
| `parse.mjs` | 마크다운 → 문서 모델. DOM을 쓰지 않는 순수 함수 |
| `views.mjs` | 화면 (트리, 홈, 문서, 검색 결과, 학회 목록·회차 상세) |
| `map.mjs` | 홈 세계지도(d3-geo + topojson, 홈에서만 늦게 불러온다)와 도시 페이지 장소 지도(Leaflet + OpenStreetMap, 핀이 있는 도시 페이지를 열 때만) |
| `search.mjs` | 검색: 부분 일치, 악센트 무시, 한글 자모 분해, 도시 별칭 |
| `html.mjs` | 자동 이스케이프 템플릿 |
| `style.css` | 스타일. 흰 바탕 + 강조색 하나(#ff385c), 시스템 글꼴. 야간 모드 없음 |
| `check.html`, `check.mjs` | 점검 페이지: 해석기 함정 시험 + 실제 콘텐츠 형식 검사 |
| `serve.ps1` | 로컬 미리보기 서버 (관리자 권한 불필요) |
| `vendor/` | 복사해 둔 라이브러리. 출처·SHA-256·라이선스는 `vendor/VENDORED.txt` |
| `data/cities.json` | 도시 도심 좌표 + 검색 별칭. 새 도시를 추가할 때 한 줄 (AGENTS.md §2.2) |
| `data/places.json` | 구글맵 공유 링크별 장소 좌표. 폰 공유 링크는 `null` (AGENTS.md §2.4) |

## 자주 하는 일

- **로컬 미리보기**: 레포 루트에서 `powershell -NoProfile -ExecutionPolicy Bypass -File site/serve.ps1`을 실행하고 <http://localhost:8000/travel-guide/>를 연다. 이 서버는 Pages처럼 `/travel-guide/` 아래에서, 대소문자를 구분해 파일을 내보낸다.
- **점검**: <http://localhost:8000/travel-guide/site/check.html>을 연다 (배포본은 `…/travel-guide/site/check.html`). 탭 제목이 `CHECK PASS`면 통과다. 실패한 시험은 이름과 기대값이 나오고, 형식 문제는 파일:줄 링크로 나온다.
- **사이트 이름 바꾸기**: `index.html`의 `<title>`·`og:title`과 `views.mjs` 맨 위의 `SITE` 한 줄을 바꾼다.
- **라이브러리 버전 올리기**: 같은 패키지의 같은 경로 파일을 jsDelivr(`https://cdn.jsdelivr.net/npm/<패키지>@<버전>/<경로>`)에서 받아 통째로 바꾸고, `VENDORED.txt`의 크기·SHA-256을 고친다. 그 뒤에 점검 페이지가 PASS인지 확인한다.
- **장소 지도 끄기**: OpenStreetMap이 접속을 막거나 정책이 바뀌면 `views.mjs` 맨 위의 `PLACE_MAP`을 `false`로 바꾼다. 그러면 도시 페이지의 장소 지도가 사라지고 Leaflet과 타일을 받지 않는다. 아예 걷어 낼 때는 `index.html` 보안 정책(CSP)의 `https://tile.openstreetmap.org`도 지운다. 접속이 막히면 오류 대신 안내 그림이 타일 자리에 뜬다.
- **코드를 고친 뒤**: 로컬에서 점검 페이지가 PASS인지, 주요 페이지(홈, 리우, 애틀랜타, 서울, 공통 팁)가 제대로 보이는지 확인한 뒤에 push한다. push하면 바로 공개된다.

## 하지 않기로 한 것 (그리고 이유)

다음 사람이나 에이전트가 "개선"하려고 다시 들이지 않도록 적어 둔다.

- **빌드 도구·npm·Node·GitHub Actions**: 아무도 관리하지 않아도 사이트가 깨지지 않게 하려는 것이다. 의존성 업데이트, 빌드 실패, Actions 권한 문제가 생길 곳이 없다. 마크다운을 push하면 그대로 반영된다.
- **CDN에서 라이브러리 불러오기**: 외부 서버가 바뀌거나 사라져도 사이트가 그대로 동작하게 하려는 것이다. 모든 파일은 `vendor/`에 복사해 두고 해시를 기록한다. 외부 요청은 CSP로 막혀 있다. 예외는 하나뿐이다. 장소 핀이 있는 도시 페이지(지금은 리우·서울·뉴욕·대전)를 열면 OpenStreetMap 지도 그림(`tile.openstreetmap.org`)을 받는다. 미리 받거나 저장하지는 않는다.
- **서비스워커·오프라인·localStorage**: 캐시가 옛 내용을 계속 보여 줘서 "고쳤는데 안 바뀐다"는 일이 생기지 않게 하려는 것이다. Pages의 기본 캐시(10분)만 쓴다.
- **날짜에 따라 바뀌는 화면** ("다가오는 학회" 등): 아무도 고치지 않으면 틀린 정보가 된다.
- **사이트 안 편집 폼, 로그인**: 서버가 필요하고, 글을 쓰는 곳은 GitHub 하나로 충분하다. 각 페이지의 "GitHub에서 수정" 링크를 쓴다.
- **마크다운 원문을 고치는 변환**: 페이지는 마크다운을 그대로 그린다. 뽑아낸 정보는 꾸밈과 색인에만 쓰고, 원문 구조(섹션 번호·순서)를 바꾸지 않는다.
- **robots.txt**: 사이트가 하위 경로(`/travel-guide/`)에 있어서 효과가 없다. 검색 노출 차단은 `index.html`의 `noindex`가 맡는다. 원문 `.md`에는 noindex를 붙일 수 없지만, 레포가 이미 공개되어 있으므로 노출 수준은 같다.
- **코드 상한**: 직접 쓴 코드는 약 2,500줄, JS 모듈 8개 이하로 유지한다. 이 안에 들어가지 않는 기능은 범위 밖으로 둔다.

## 인계

- Pages 설정은 레포 관리자만 바꿀 수 있다. 관리자가 바뀌면 Settings → Pages가 `main` / `(root)`인지 확인한다.
- 사이트 주소는 레포 이름에서 나온다. 레포 이름을 바꾸면 주소도 바뀐다 (코드는 상대 경로를 쓰므로 그대로 동작한다).
- 문제가 생기면 먼저 점검 페이지를 연다. 그다음에는 브라우저 개발자 도구의 콘솔을 본다.
